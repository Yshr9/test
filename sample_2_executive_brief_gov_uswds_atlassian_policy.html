コーディングエージェント活用方針

目的：開発部門（PDE）における AI コーディングエージェントの今後の活用方針を、情報システム部門・経営層に提案し、ライセンス整備・規約確認・全社方針確定の判断材料とする。

宛先情報システム部門／経営層
提案元製品開発部門（PDE）／執行役員CBO 山田泰裕
日付2026年6月19日
文書区分提案（最終決定は経営層・情シス）

結論

Claude Code を PDE の標準とする。Codex は申請制で併用する。

標準は固定化せず、AI業界の変化を踏まえて定期的に見直す。資産は Markdown 等で相互移行でき、ロックインの懸念は限定的。

1. 提案内容

  • Claude Code を PDE の標準コーディングエージェントとする。
  • 完全な1本化は行わず、Codex 等の併用を申請制で認める（プロジェクト／役割単位で付与）。
  • 標準は固定化せず、期間を区切って検証し定期的に見直す。

2. Claude Code を標準とする理由

  • コードの正確さ。正確性が重要なコード（PF運用の IaC 等）で安定。
  • 複雑・探索的タスクへの強さ。設計・探索、IaC、Android 設計・画面生成で差が出る。
  • ドキュメント・図表生成品質。仕様書や SVG 等の図表で品質が高い。
  • Atlassian 連携の使い勝手。Confluence／Jira 連携で現状優位。
  • 企業姿勢・長期継続性への信頼。長寿命プロダクトに適した安定性。
  • プラン経済性。Team Premium に利用枠がバンドルされ予算化しやすい。

3. 完全一本化しない理由

単一ベンダーへの完全一本化はリスクと機会損失を伴うため行いません。

  • Codex が有効な局所的タスクがある。全タスクの約3割は Claude Code 単独では取りこぼしがあり、その用途で有効。
  • 初期コーディングのたたき台に使える。「Codex で初期コーディング → Claude Code で検証」が機能。
  • 相互レビューに使える。片方のプランをもう片方が精査・レビューする併用が機能。
  • 外部パートナーは現状 Codex 中心。整合は段階的でよい。

!AI業界の流動性

AI業界は流動的で、半年〜数年で優劣が変わり得る。標準は当面の最適解であり、未来永劫の固定ではない。コンテキストはソースコード側にあり、スキル／プロンプト／メモリは Markdown 等で相互移行可能なため、将来の移行コストは小さい。

4. ガバナンス確認事項

基本要件は入力データがモデル学習に使われないこと。以下を全社情報セキュリティ方針と突合してください。

学習不使用入力データがモデル学習に使われないこと（基本要件）。
ZDRゼロデータ保持の要否はポリシー次第。必須なら Enterprise 相当が要件。
データレジデンシー日本データレジデンシーの要否確認。
SSO / SCIMシングルサインオン・プロビジョニング要件の確認。
監査ログ監査ログの取得・保持要件の確認。

5. 判断が必要な事項

!情報システム部門・経営層が判断すべきこと

  1. Claude Code（Team Premium 相当）席を開発部門の標準として整備するか。
  2. Codex／技術サポート向け ChatGPT を用途・役割単位で申請付与する仕組み・予算枠を設けるか。
  3. 各ツールの規約・セキュリティ要件（学習不使用／ZDR／データレジデンシー／SSO／監査）の適合可否。
  4. 外部パートナーのライセンス整合方針（現状 Codex → 標準との整合）。
  5. PM/BL・技術サポートのツール付与方針の確定。
  6. 定期的な見直しサイクルのプロセス合意。

?未決事項・確認が必要な事項

  • ZDR が必須か否か（全社情報セキュリティポリシー次第）。Team／Business プランの ZDR・データレジデンシー対応状況は要確認。
  • 外部パートナーのライセンス整合のタイミング・要否。
  • 価格・契約条件は資料に記載された範囲を超えて断定しない（最終判断は「価値あたりコスト」で行う）。
