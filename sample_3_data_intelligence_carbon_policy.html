本資料は、開発部門（PDE）における AI コーディングエージェントの今後の活用方針を情報システム部門に提案するもの。トライアル制度（2026年6月受付終了）を経て、現場の利用実態と部門横断の協議に基づき取りまとめた。
02

Decision Architecture

方針の骨格
Standard
Claude Code

PDE の標準コーディングエージェント。全員に標準整備する。

Exception
Codex

完全1本化はしない。プロジェクト／役割単位の申請制で併用を認める。

Review Cycle
定期見直し

標準は固定化しない。AI業界の変化を踏まえ期間を区切って検証・更新。

Migration
移行可能

スキル／プロンプト／メモリは Markdown 資産で相互移行可能。ロックイン懸念は限定的。

ロックイン整理：コンテキストはソースコード側にあり、CLAUDE.md / AGENTS.md は片方をメイン・もう片方を参照として共通化できる。一部マーケットプレイス由来のスキルは片寄せ懸念があるが、AI による相互変換が可能で移行コストは小さい。
03

Tool Positioning

ツールの適性と扱い

Claude Code

Standard ／ コーディング
  • コードの正確さ、複雑・探索的タスクへの強さ
  • ドキュメント・図表生成の品質
  • Atlassian（Confluence／Jira）連携の使い勝手
  • 企業姿勢・長期継続性への信頼／プラン経済性

Codex

Exception ／ 申請制
  • 局所的タスク・コスパ重視で有効
  • 初期コーディングのたたき台
  • Claude Code との相互レビュー
  • 外部パートナーは現状 Codex 中心

ChatGPT（チャット）

Limited ／ 限定用途
  • 技術サポートロールでの難解な技術文書読解
  • 該当ロールに限定して利用許可を推奨
  • コーディングエージェント用途ではない

PdM／BL・技術サポート

非コーディング対象
  • PdM／BL はチャットUI用途（Claude か ChatGPT）に統一を検証
  • 開発と必ずしも揃える必要はない
  • 役割別に検証・整理（端村・こだま／田崎）

05

Governance & Contract Requirements

情シス確認依頼
学習不使用基本要件

入力データがモデル学習に使われないこと。商用規約で満たせば当面は十分。

ZDR要否確認

ゼロデータ保持の要否はポリシー次第。必須なら Enterprise 相当が要件。

データレジデンシー要確認

日本データレジデンシーの要否確認。

SSO / SCIM要確認

シングルサインオン・プロビジョニング要件。

監査ログ要確認

監査ログの取得・保持要件。

外部パートナーライセンス要整合

現状 Codex → 標準との整合方針を決定（段階的でよい）。

06

License Model

対象別ライセンスの考え方
対象ライセンス方針区分
Claude Code 標準利用者Team Premium 相当（Claude Code ＋利用枠込み）。利用量が読みやすく予算化しやすい。標準整備
Codex 申請利用者軽用途は従量の Codex 専用席。常用ヘビーは Business 席＋従量。申請付与
技術サポート向け ChatGPT難解な技術文書読解に限定。該当ロールに限定して付与。限定付与
「価格」ではなく「価値あたりコスト」で判断する。価格だけで優劣は決まらない。最終判断はライセンス費ではなく「価値あたりコスト（有効PR／有効調査あたりの総コスト）」で行う。価格・契約条件は資料に記載された範囲を超えて断定しない。
07

Requests & Next Actions

情シスへの依頼・部門側アクション

情報システム部門への依頼事項

1
Claude Code（Team Premium 相当）席を開発部門の標準として整備。
2
Codex／技術サポート向け ChatGPT を用途・役割単位で申請付与する仕組み・予算枠の整備。
3
各ツールの規約・セキュリティ要件（学習不使用／ZDR／データレジデンシー／SSO／監査）の適合確認。
4
外部パートナーのライセンス整合方針の決定。
5
PM/BL・技術サポートのツール付与方針の確定。
6
定期的な見直しサイクルのプロセス合意。
